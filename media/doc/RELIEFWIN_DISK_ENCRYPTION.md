# ReliefWin 磁盘加密

本功能正在开发。当前工作区中的代码不能视为已完成的系统盘加密产品，
不能在唯一副本的数据卷上启用。尚未完成的端到端验证会在本文件中明确记录。

## 用户确认的范围

- 系统盘和数据卷；全新卷和已有卷的原地加密。
- 密码与独立恢复密钥；名称为“ReliefWin 磁盘加密”，在设置中管理。
- 采用公开格式，不要求与 Windows BitLocker 互通。
- 系统卷转换从外部安装 ISO／恢复 U 盘执行；数据卷独占、卸载后转换，支持中断后继续。
- 密码为 12–128 个可打印 ASCII 字符，恢复密钥使用独立生成的 256 位随机数。
- 启动前使用图形解锁界面，默认简体中文，可切换英语和日语；提供密码与恢复密钥入口。

## 格式与证据

正常状态的卷使用分离式 LUKS2 加密头，数据偏移为零。
分离加密头避免为原地加密移动或缩小文件系统。加密头和转换日志必须放在
目标卷以外的未加密存储中；使用启动分区的
`\EFI\ReliefWin\Encryption`。恢复密钥不能替代加密头备份。

- [LUKS2 On-Disk Format Specification](https://gitlab.com/cryptsetup/LUKS2-docs/-/raw/main/luks2_doc_wip.pdf)：
  大端字段、4096 字节二进制头、双份元数据、序号、SHA-256 校验、JSON、分离头、
  密钥槽、密钥摘要、`offline-reencrypt` 要求。
- [LUKS1 On-Disk Format Specification 1.2.3](https://gitlab.com/cryptsetup/cryptsetup/-/raw/main/docs/on-disk-format.pdf)：
  2.4 节 AF splitter、H1 的大端计数器和每块独立扩散；4000 条带。
- [NIST SP 800-38E](https://doi.org/10.6028/NIST.SP.800-38E)：XTS-AES 磁盘数据保密模式。
- [RFC 8018](https://www.rfc-editor.org/rfc/rfc8018#section-5.2)：PBKDF2。
- [Microsoft SymCrypt](https://github.com/microsoft/SymCrypt)：SHA-256、HMAC 和 PBKDF2，保留 MIT 许可。
- [BearSSL v0.6](https://bearssl.org/gitweb/?p=BearSSL;a=tree;hb=v0.6)：原样引入的恒定时间
  AES ct64 原语和 HMAC-DRBG，保留 MIT 许可；XTS 组合与格式解析在本项目实现。
  未复制 Linux 或 cryptsetup 的实现代码。
- [Microsoft HwStorAdapterControl](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/storport/nc-storport-hw_adapter_control)：
  `ScsiStopAdapter`／`ScsiRestartAdapter` 的电源管理契约及 DIRQL 调用约束。

当前受支持的格式配置为 AES-256-XTS（两个独立 256 位 AES 密钥）、512 字节加密单元、
PBKDF2-HMAC-SHA256、SHA-256 AF splitter 和密钥摘要。
不支持的算法、扇区大小、转换扩展和强制要求会被拒绝，不能静默降级。
这是一种 LUKS2 配置的实现，不代表已实现 LUKS2 的全部可选算法和扩展。

`config.requirements.mandatory` 的对象形态经过 cryptsetup 2.4.3 的
`reencrypt --encrypt --init-only` 输出验证。规范正文对该属性的“array”描述
不够精确；实现采用公开工具实际生成、可识别的对象形态。

## 转换事务

转换前将 LUKS2 元数据标记为 `offline-reencrypt`；任何正常激活路径都必须拒绝该状态。
卷保持离线，独占访问，禁止同时修改元数据或挂载文件系统。

日志包含两个 4096 字节状态记录和一个 1 MiB 数据区。状态记录绑定卷的稳定标识、
LUKS UUID、方向、长度、进度和待提交区段摘要，并以独立派生的 HMAC-SHA256 密钥认证。
密钥派生有固定的域分隔，不在日志中保存密钥或口令。

一次转换先持久化两个一致的已完成状态，再写入并刷新区段日志，
随后持久化两个待提交状态，最后改写并刷新目标数据，持久化两个已完成状态。
加密时日志存储输出密文；解密时日志存储输入密文。因此重放不会二次加密，
目标区段发生半写入时仍可恢复。日志损坏或认证失败时停止，不能猜测进度。
调用者必须在返回错误后重新读取日志；内存进度不代表已持久化进度。

刷新语义以存储设备正确执行 flush 为前提。固件、控制器或硬盘虚假确认写入，
以及同时损坏所有日志副本和目标数据，不能靠软件日志恢复。

## 安全边界

XTS 提供静态数据保密性，不提供每扇区篡改认证。普通 LUKS2 头校验也不是
防恶意篡改的签名。此功能不宣称提供 Secure Boot、TPM 测量启动、
防离线回滚、内存攻击防护或 FIPS 认证。

自定义管理 IOCTL、卷描述符、转换日志和启动交接结构均为 ReliefWin 私有 ABI，
不修改或扩充 Windows 内核结构。卷描述符使用显式大端字节序，
MBR 绑定磁盘签名及分区范围，GPT 绑定磁盘 GUID、分区 GUID 及分区范围。
描述符记录系统卷属性，避免加密后无法识别文件系统而绕过外部恢复环境要求。
启动密钥经专用驱动导出的数据区传递，不写入 BCD、注册表、磁盘或调试日志。
启动加载器保存在未加密启动分区，密码或恢复密钥解锁后才能加载系统文件。
图形界面提供遮蔽输入、光标编辑、Tab／Enter／Esc 导航、鼠标／触摸按钮和内联错误提示。
切换密码与恢复密钥模式、取消和完成密钥派生后清除输入缓冲区。
恢复密钥须输入 64 位十六进制字符；没有可用图形输出时拒绝启动解锁。
随机源使用 UEFI RNG，x86 可回退到 RDSEED／RDRAND；没有可用熵源时拒绝生成密钥。
内核使用启动时注入的熵初始化 HMAC-DRBG，不以计时器或进程信息替代密码学熵。
生成恢复密钥时，`.rwbackup` 保存分离头、卷标识和恢复密钥，旁边的 `.rwbackup.txt`
保存可在启动前输入的恢复密钥；两个文件均在生成时回读核对，并需一起离线保管。

## 定向验证

宿主测试使用 OpenSSL 独立后端和地址／未定义行为检查器，生产目标使用相同核心、
SymCrypt 哈希后端和 BearSSL AES 原语。测试覆盖格式校验、错误口令清零、两个密钥槽、主头损坏恢复、
序号冲突、未知要求、算术边界、加密和解密各 I/O 步骤中断及半写入重放。

cryptsetup 2.4.3 已识别生成的分离头，使用密码和恢复口令解锁，并验证恢复出的卷密钥
逐字节相同。反向读取 cryptsetup 创建的 AES-XTS／PBKDF2／512 字节扇区头也已通过。
cryptsetup 还成功解锁了实际的 4 GiB 加密 NTFS 系统卷，独立读取的 4096 字节文件
与加密前逐字节一致，并通过标准 dm-crypt 映射完成了离线驱动部署及回读核对。

amd64 虚拟机中已验证数据卷原地加密和解密、暂停续转、错误密码拒绝、
密码与恢复密钥轮换、文件读写及完整字节比较。驱动测试同时覆盖异步通知转发、
不修改写入源缓冲区和锁定卷访问拒绝。恢复镜像包含管理器与过滤驱动。
数据卷管理测试完成 50 项检查，包括恢复密钥文本导出、将恢复备份还原到原卷、
拒绝错误卷，以及操作期间保持已加密系统卷的描述符不变。
4 GiB 测试系统卷已验证转换暂停、重启后拒绝未完成转换的卷、从外部 ISO 完成续转，
以及分别通过密码和恢复密钥启动进入桌面。更新后的过滤驱动通过 23 项系统卷检查，
包括普通文件、内存映射文件的读写与刷新，以及原始文件的逐字节比较。

最新宿主核心测试完成 1490 项检查，地址／未定义行为检查器未报告错误。
图形界面的有界输入、清零、格式校验和间歇指针事件通过 165 项宿主检查；
这是 ReliefWin 自有启动界面测试，不是 Windows BitLocker 行为兼容性测试。

实际 GUI 验证通过键盘完成；固件指针协议的鼠标和触摸输入尚未获得端到端实测。
