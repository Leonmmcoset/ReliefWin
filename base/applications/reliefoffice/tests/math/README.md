# ReliefMath validation

Run `python3 base/applications/reliefoffice/tests/math/run-host.py` on Linux with Clang, ASan/UBSan, and development packages for Cairo and FreeType. The script reuses `/tmp/reliefoffice-math-host` and runs the imported model, bounded protocol, exact native document/atomic storage/recovery, and background file job suites, followed by 68 renderer checks. The renderer checks exercise actual formula parsing, FreeType outlines, SVG paths, raster alpha, PNG output, Chinese glyph fallback, and invalid settings. Host rendering uses the host Cairo/FreeType libraries; it does not establish that the Windows dependency build works.

Build `reliefmath_tests` using the operating system build. Copy this test binary temporarily beside the installed `reliefmath-render.exe` and `ReliefMath/STIXTwoMath-Regular.otf`, then run it. It launches the real renderer and checks bounded protocol identity, PNG/SVG/RGBA results, cancellation, restart, and background Unicode document saves/loads with immutable snapshots and stale-stamp rejection. The optional `--timeout` run also blocks a renderer's input, cancels a pending overlapped write, reuses the client, and verifies the ten-second request timeout. The test executable is not included in the product image.

Run `reliefmath_tests --public-volume D:/` separately on a FAT volume. Its 24 checks exercise real `.rmath` save/read/replace operations, stale-stamp rejection, explicit public metadata for a filesystem without ACL support, and rejection of private recovery storage there. The shared document-mode helper accepts ordinary document storage only when strict permissions succeed or the filesystem explicitly reports unsupported security and public metadata. Recovery keeps its owner and private-permission requirements.

`process_win32.cpp` follows Microsoft's documented `CreateProcessW`, `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`, `CreateNamedPipeW`, `WriteFile`, `GetOverlappedResult`, `CancelIoEx`, and `PeekNamedPipe` contracts. Request buffers remain owned until pending writes complete or cancellation has been drained. The GUI polls process completion and output; the worker processes one request at a time. A private inherited handle list contains only the worker's standard input, output, and diagnostic sink.

The worker uses explicit `_read` and `_write` from the same UCRT as `_fileno` and `_setmode`. The legacy `read` and `write` aliases can bind to MSVCRT through the build's old-name library, which gives them a separate descriptor table and text mode. The native PNG/SVG/raster test exercises the binary protocol across this boundary, including the PNG signature's CR/LF and control bytes.

Cairo 1.18.4 and Pixman 0.44.2 are built statically from the released sources recorded in `thirdparty/sources.json`. Cairo uses its image, recording, user-font, and PNG facilities; ReliefMath derives SVG directly from the actual Cairo path and derives glyph outlines using the existing FreeType engine. A small user-mode diagnostic implementation provides the `FT_Message` and `FT_Panic` functions deliberately omitted from the operating system's shared FreeType library. The font bytes stay alive until the FreeType faces are released, and paths enter the filesystem through the shared UTF-8 Windows helper.

Windows provides no documented per-directory durability flush equivalent used by the shared storage shim; directory `fsync` is an explicit portability limit. Host tests and a Windows-compatible virtual machine do not establish Windows 11 behavior or untested hardware behavior.

The original AMD64 worker failed with `Code::Protocol` and `Invalid frame magic`: legacy `read`/`write` aliases bound to MSVCRT while `_fileno` and `_setmode` came from UCRT. Text-mode LF expansion inside a framed SVG changed the physical payload size. Explicit UCRT `_read`/`_write` fix that transport. The first nominal old/new comparison still used the original installed worker, confirmed by offline SHA-256 `3e4ae8898599ea7176840025d671b83e3efded148fcead9fcd0d19cf629ca057`; those failures were not failures of the rebuilt artifact. Actual replacement first passed the earlier 36-check test, preserved in `/tmp/reliefwin-brand-host/previous-guest-logs/math.log`. The final 41-check run adds the positive existing-target overwrite coverage.

The original FAT long-name test failed its first save after installing the document because it assumed the temporary file ID survived rename. Microsoft's [BY_HANDLE_FILE_INFORMATION contract](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-by_handle_file_information) permits FAT file IDs to change on rename to a longer name. Storage now compares the still-open writer's current post-rename identity with an opened read-only installed reference. That reference stays alive while the writer closes; final metadata is queried afterwards because the [WriteFile contract](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-writefile) defers complete last-write-time updates until writer handles close. Post-rename failures preserve the installed document. This fix passed the first native FAT save and then exposed the old shared save lock's open-target restriction on the second save. The final directory-query identity-lock build passes both saves and all 24 checks.
