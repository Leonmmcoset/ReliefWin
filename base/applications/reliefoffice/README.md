# ReliefOffice for ReliefWin

This is a source port of the seven ReliefOS applications, pinned to the revision in `upstream.json`. It retains their document models, parsers, editing operations, import/export paths and Simplified Chinese translations. `UPSTREAM_LICENSE` and `UPSTREAM_NOTICE` preserve the original Apache 2.0 terms and attribution. New platform and test files state their own licenses.

| Application | Native format | Existing interchange formats |
|---|---|---|
| ReliefWord | `.rword` | TXT, HTML |
| ReliefExcel | `.rexl` | CSV |
| ReliefPPT | `.rppt` | PNG slide export, HTML presentation export; PNG/BMP pictures |
| ReliefTodo | `.rtodo` | CSV and Markdown export |
| ReliefDiagram | `.rdiagram` | SVG, PNG and Markdown outline export |
| ReliefMath | `.rmath` | SVG, transparent PNG and LaTeX export |
| ReliefMath++ | `.rmathpp` | SVG and PNG view export |

The installer ISO carries the suite under `deployment/ReliefOffice` as an offline payload. Its setup tree mapping copies that payload to the installed system's `%SystemDrive%\Program Files\ReliefOffice`, where installed-system setup registers it. The preinstalled image carries the suite directly in that installed directory and registers it during mini setup. The Live environment can carry the separate deployment payload in RAM; it has no installed Office directory, registration or shortcuts.

Setup creates seven all-user shortcuts in Start Menu → ReliefOffice, registers only the seven native extensions, and adds one suite entry to Add/Remove Programs. It creates no desktop shortcuts. Existing native-extension handlers are preserved by the INF's no-clobber flags. The uninstaller checks the installation directory, shortcut targets and association commands before removing items it owns. It deletes a fixed file manifest and retains user documents and recovery files. A partial failure keeps a retryable uninstall entry; removal of its running executable is scheduled for reboot.

The FLTK 1.4.4 frontend uses its native Windows GDI backend, UTF-8 widget strings, Noto Sans SC and embedded Chinese catalogs. The shell entry point converts UTF-16 filenames to UTF-8. Clipboard ownership uses `GetClipboardSequenceNumber`. File operations and joinable workers use the shared Windows platform layer documented in `platform/README.md`. Math++ calculations and Math rendering remain isolated child processes with cancellation and bounded execution. ReliefMath uses the existing FreeType target, its original STIX Two Math font, and static Cairo/Pixman/PNG libraries.

The suite uses the UCRT headers and runtime consistently, including its static libraries. The `reliefoffice_cppstl` link interface retains the existing C++ runtime without inheriting its system include ordering, which would otherwise select legacy CRT headers before UCRT. No C runtime file object or descriptor is passed to another C runtime.

`thirdparty/sources.json` records dependency versions, download URLs and archive hashes. The FLTK adaptations add its missing Windows IME include, the public monitor-info pointer cast and double `ceil` overloads for the i386 UCRT. The latter preserve the already computed float value while avoiding an unavailable i386 `ceilf` import. Other library configuration is in `dependencies.cmake` and `cairo.cmake`. `THIRD_PARTY_LICENSES.txt` is installed with the suite. The application icons are unmodified Microsoft Fluent UI System Icons; `icons/sources.json` records their sources and hashes.

Build the seven application targets and `reliefmath_render` through the existing OS build. Test executables are build targets only and are excluded from shipping images:

```sh
CCACHE_DISABLE=1 ninja -C output-Clang-amd64-debug reliefword reliefexcel reliefppt \
    relieftodo reliefdiagram reliefmath reliefmathpp reliefmath_render \
    reliefoffice_formats reliefoffice_io reliefoffice_install_smoke
python3 base/applications/reliefoffice/tests/run-host.py
python3 base/applications/reliefoffice/maintenance/test_maintenance.py
```

`reliefoffice_formats --verify <fixtures>` compares the seven actual encoders/parsers with byte fixtures generated by the unmodified Unix revision. `reliefoffice_io <fixtures> <writable-directory>` exercises real save, recovery, Unicode path and worker operations. `reliefoffice_install_smoke` checks installed files, associations, shortcut targets and actual application windows. The host regression runner uses the original model/document/layout tests and a fixed, reused build and data location. Host checks do not establish Windows filesystem or Windows 11 parity; actual guest results and their limitations belong in the validation report.
